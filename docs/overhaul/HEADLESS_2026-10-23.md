## What stayed, and why (the judgment calls)

The brief listed several modules as reachability candidates. Each turned
out to be genuinely load-bearing for the one surviving entry path
(main-engine / MCP-submitted), not book-only — deleting them would have
been a regression, not a cleanup:

- **`book_params.py`** — `executor.maybe_execute`'s per-trade feasibility
  gate calls it (via `services.risk.books.main_engine_spec`) for every
  live trade now, book or not. It resolves the stop/leverage/notional
  floor when no per-entry config block exists, which is now always.
  `apply_notional_ceiling` (book-only) is deleted; the rest stays.
- **`shadow_ledger.py`** — `executor.py`'s `thin_short_relax` live
  experiment (W-G1) records to it on every thin-short rejection, unrelated
  to any book. `dashboard.py` also still imports it directly for the
  (now historical) book-league/news/tapes panels — see "Dashboard" below.
- **`rebalancer_owned.state_file()`** — the shared state-directory
  resolver every other agent module routes through in tests
  (`perception.py`, `data_logger.py`, `shadow_ledger.py`, `dashboard.py`,
  `metrics.py`, `scripts/preflight_live.py`, `scripts/_state_env.py`).
- **`data_logger.py`** — feeds the dashboard's funding-heat panel (general
  market data, not book-specific); `scripts/trading_loop.py` still calls
  it every cycle.
- **`capital_flows.py`** — deposits/withdrawals tracking for the
  flow-neutral drawdown; `dashboard.py` imports it directly at module scope.
- **`news_catalyst.py`** — `research.py`'s news-headline fetch for EVERY
  coin research call (main-engine and MCP `research` tool alike), never
  book-gated.
- **`deadline.py`** — `scripts/trading_loop.py` still wraps
  `data_logger.maybe_log` in `with_deadline`; the wedge it guards against
  (a stalled network recorder blocking every subsequent DSL exit) is just
  as real with one recorder as it was with four.
- **`unlock_map.json`** — the brief said delete it "if only [unlock_recorder]
  uses it"; `services/intel/desk_rules.py`'s `crypto_tickers()` (used by
  `services/intel/sources/catalysts.py` for the MCP desk briefs' crypto/
  token-unlock catalyst detection) reads the same file, with a documented
  fallback if it's missing. Restored after an initial over-eager delete.

A real gap this exposed in `tests/test_repo_hygiene.py`'s own reachability
guard: its BFS never traced into `NOT_CLEANUP_OWNED` files (`executor.py`,
`sizing.py`, `risk_gates.py`, `hyperfeed.py`), so a module reachable ONLY
through `executor.py` (book_params.py, shadow_ledger.py) looked unreachable
the moment the one entry-point-direct importer of each
(`scripts/autonomous_cycle.py`) was deleted — a false positive the test
would have thrown on this very cleanup. Fixed by tracing through those
files' imports too (while still excluding them from the reachability
*requirement* — only cleanup-owned modules are checked).

## `services/risk/books.py` — the one real design decision

`BOOK_NAMES` is now `()`. The naive read of "no books" is
`all_book_specs()` returning `[]` — but `derive_limits` computes
`can_trade = any(r.can_trade for r in rows)`, so an empty roster makes
EVERY risk-limits reader (the dashboard risk panel, `GET /api/risk/limits`,
the MCP `risk_limits` / `risk_size_trade` tools) report "cannot trade" on
a well-funded account. Caught by `services/risk/tests/test_api.py`'s
existing `test_get_limits_uses_the_mocked_active_equity` (expected `len(books)
== 7`, got `1`) and a hand-check against `derive_limits` directly before
fixing it. The fix: `all_book_specs()` returns a one-item roster built by
a new `main_engine_spec()` — the same `BookSpec` shape `executor.py` builds
inline for its own feasibility check, `enabled` forced `True` (there is no
more per-entry config block to read it from). `executor.maybe_execute` was
changed to call `risk_books.main_engine_spec()` instead of duplicating the
construction, so the two surfaces can't drift apart.

## Dashboard — frozen, not gutted

The brief's "freeze" instruction: no deletion of `pathiel/dashboard.py`,
remove only dead panels that reference deleted code. On inspection,
`dashboard.py` references NO deleted Python module — `_BOOKS` is a static
7-entry list of name strings (not imports), and `_books_payload`,
`_book_league_payload`, `_tapes_payload`, `_news_payload` all degrade
gracefully: with no book config blocks, every book row already showed
`status: "off"` before this cleanup (the books were disabled since
`5fb6fca`) and shows the same `"off"` now, for the same reason. The
book-league/news/tapes panels read `shadow_ledger.load(book)` for the
seven retired book names — `shadow_ledger.py` stays, so these calls still
work; they will just never see a new row, which is an honest historical
view of what the books did, not a broken page. Nothing was removed from
`pathiel/dashboard.py`. A frozen note was added to README.md's dashboard
section instead (see below) and `services/wallet_ui/README.md`.

## `scripts/preflight_live.py` and `scripts/profit_audit.py`

Both are KEEP scripts with real book-specific content mixed into otherwise
general-purpose tooling — fixed in place, not deleted:

- `preflight_live.py`'s `check_books` loaded `scripts/autonomous_cycle.py`
  via `importlib` (a hard crash now) and `check_book_reachability` checked
  a per-book allowlist-coverage concern with no referent left. Both
  removed. `check_capital` / `check_margin_headroom` already derive
  through `services.risk.books.all_book_specs`, so they correctly report
  the one-entry-path reality (fixed by the `books.py` change above, not by
  anything in this file).
- `profit_audit.py` is ~900 lines of general account profitability
  auditing (fees, liquidations, funding, HIP-3 growth-mode discount,
  pair-trade stats) with exactly three book-specific pieces mixed in:
  `CURRENT_BOOK_ROSTER`, `book_roster_staleness()`, and
  `load_pnl_by_book_priority()` (which imports the now-deleted
  `pnl_by_book.py`). Those three — and their report section, and their
  tests in `tests/test_profit_audit.py` — are removed; the other 46 tests
  in that file are untouched and pass.
