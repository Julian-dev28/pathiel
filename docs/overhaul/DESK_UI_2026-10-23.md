# Desk UI (agent: desk-ui, 2026-10-23)

Branch: `oil-desk-ui` off `overhaul-2026-10-17` at `4b4f817`, rebased onto
`434312b` (`grade-everything` + `mcp-oil-only` + `headless-desk` merged).

Operator decision, 2026-10-23: pathiel is a headless desk. Claude runs a
15-minute MCP loop (`.claude/skills/oil-tick/SKILL.md`) that trades a small
pathiel wallet through `place_bracket`/`bracket_sweep`
(`pathiel/agents/bracket.py`); the operator trades their own wallet by hand
at their own chosen leverage from the same thesis. The dashboard that used
to watch the autonomous bot (scan feed, book panels, AI-brain trend tab,
trade tape) has nothing left to watch. This agent rebuilds it around the
new workflow: one screen, the decision first, small tables, nothing to
hunt for — vanilla HTML/CSS/JS served by the FastAPI server, no framework.

**The product is a generic desk UI, not an oil-only one.** Other
`DeskSpec`s (`btc`, `top5`, `ai`, `metals`, `indices`) stay registered in
`services/strategies/desks/*.py`, reachable by a direct link or a script.
The UI only shows desks listed in agent config's `active_desks` (default
`["oil"]`) — one active desk renders with no switcher, several show a
small tab row (the switching code stays wired either way). Oil is the only
desk actually trading today, not the identity: the plan is to master oil
first, then turn on indices, ETFs and other commodities the same way.

## The one screen: "/" (the Desk page)

Sections, top to bottom (`pathiel/templates/oil_desk.html`,
`pathiel/static/oil_desk.js`):

1. **Onboarding** (`#onboarding-root`) — shown instead of the Desk, for a
   brand-new visitor only: connect account → risk preset → done. Ported
   verbatim from the old landing page, minus the per-book feasibility
   preview (books are gone).
2. **The call** (`#call-section`) — the active desk's thesis in quick
   markdown (`services/thesis/render.py::render_markdown`, the same
   renderer the MCP `desk_brief` tool uses in quick mode), plus the 20x
   line: liquidation price, stop distance as a share of it, a plain
   verdict ("20x OK" / "no 20x: max Nx"), and R to each target — computed
   from the call's own entry/stop/targets by
   `services/strategies/call_line.py`, using `pathiel/agents/bracket.py`'s
   `check_levels`/`check_leverage` and `pathiel.client.exchange.
   get_max_leverage`. A 5/10/20 leverage selector recomputes it
   server-side (`GET /api/desks/{id}/line?leverage=`). The same line
   renders on the Thesis tab's leverage picker, via the same endpoint.
3. **Wallets** (`#wallets-section`) — one row per registered account (the
   active trade account and every watch account): equity, each position
   with entry/leverage/liquidation/distance/uPnL, its stop and target
   levels, and a red NAKED badge when no reduce-only stop covers it.
   `GET /api/accounts/{id}/positions`
   (`services/accounts/positions.py::fetch_positions_for_account`, moved
   out of `scripts/watch_wallet.py`'s `assess()`), across the main dex and
   every HIP-3 dex the account holds margin on.
4. **Levels** (`#levels-section`) — mid, last closed 1h candle, 8h/24h/48h
   range, ATR14, where the mid sits in the 24h range, for the active
   desk's primary instrument. `GET /api/desks/{id}/levels`
   (`services/strategies/levels.py::summarize_coin`, moved out of
   `scripts/oil_levels.py`).
5. **Headlines and catalysts** (`#intel-section`) — the intel the thesis
   already carries (`DeskBrief.intel`/`.thesis.catalysts`): upcoming
   catalysts, the top headlines by relevance with a bull/bear/neutral
   chip, prediction-market odds. A Hormuz/ceasefire headline is the loop's
   invalidation trigger, so it belongs on the one screen, not only buried
   in the full thesis. Capped to 6 rows per list (small tables).
6. **Loop log** (`#log-section`) — the last 30 lines of the active desk's
   loop. `GET /api/desks/{id}/log` (`services/strategies/desk_log.py`,
   moved out of... itself, generalized from oil-only to
   `PATHIEL_<DESK>_LOG` per desk id, `PATHIEL_OIL_LOG` unchanged for
   `desk_id="oil"`). Missing file renders "no ticks yet".
7. **Track record** (`#track-section`) — `DeskBrief.track_record` (n
   graded, direction hit rate, mean return, mean Brier).
8. **Old auto-trader kill switch** (`#stop-section`) — the STOP TRADING
   control survives, relabeled: it sets agent config `mode: OFF`, which
   only disables the retired bot's own `execute` path. It does not stop
   the oil-tick loop (`place_bracket`/`bracket_sweep`) or the operator's
   own trades — the label says so, because an off switch people misread
   is worse than no off switch.

Refreshes every 30s via `pathiel.js`'s `pollEvery` (never stacks a poll
behind a slow read, pauses while the tab is hidden). Every section loads
and fails independently — one source failing shows that section's own
inline error, never a blank page.

### 1. Thesis/Account loading slowly — before/after

**What actually blocked.** Not the page handler (`GET /desk/{id}`,
`GET /account` — both `async def`/plain `def` with no venue call, already
sub-10ms) and not the event loop (every data route here is a plain `def`,
which FastAPI already runs on its thread pool, off the loop). The real bug
was inside `services/strategies/facade.py::_analytics_for_brief`: a desk with
**no analytics cache file at all** — never built, ever, on this state dir —
fell through to a live, synchronous, multi-instrument candle build
**regardless of the caller's `wait` flag**. The web route
(`services/strategies/api.py`'s `get_desk_brief`/`get_call_line`) always
calls `get_brief(desk_id)` with `wait=False`, so that whole build ran inside
the one request the Thesis page's first fetch was waiting on — measured
against a genuinely cold `candle_store` (today's active desks, metals/ai
newly turned on): **ai 24.0s, top5 9.1s, oil/gas/btc 0.1–0.5s**. The
operator's own report ("Thesis... loads slowly with a blank screen") is this
bug, hit on any desk whose cache is cold — right after a restart, or the
first time a newly-activated desk is opened.

Fix: `_analytics_for_brief` now only builds inline when `wait=True` (MCP,
CLI — `scripts/pathiel-mcp-server.py`, `services/strategies/__main__.py`,
no page to come back and update later) **or** when a cache exists but is
unusable for a different reason (built for a now-retired primary instrument
— that case stays eager: a stale wrong-coin ladder must never be served even
once). Every other cold-desk web request now queues an urgent background
build (`facade.revalidate(desk_id, urgent=True)`) and returns at once with
`analytics=None, refreshing=True` — the same shape `DeskBrief` already uses
for "stale, rebuilding" — so the existing frontend poll (`desks.js`'s
`followRefresh`) picks it up with no new wiring.

| | before (cold desk, `wait=False`) | after |
|---|---|---|
| `GET /api/desks/ai` (never built) | 24.0s (measured directly) | 9ms |
| `GET /api/desks/top5` (never built) | 9.1s (measured directly) | <10ms |
| `GET /desk/{id}` page shell | already <10ms | unchanged |
| `GET /api/desks/oil`/`gas`/`btc` (candle_store already warm) | 0.1–0.5s | unchanged (not the bug) |
| `GET /account` page shell | already <2ms | unchanged |
| `GET /api/accounts/active/summary` (cold account read, 11 dexes) | ~1s (one-time; shared-snapshot cache already makes every later poll ~30µs) | unchanged — this was never the multi-second bug, see below |

No new routes: the fix is entirely inside `get_brief`'s existing
stale-while-revalidate policy, so `tests/test_no_blocking_on_the_event_loop.py`'s
route table needed no new rows (it already globs `services/*/api.py` —
`services/strategies/api.py`'s routes are unchanged, still plain `def`,
still off the loop).

**Venue meta caching** (the task's point (c)) was already in place and did
not need new work: `pathiel.client.exchange._META_CACHE` (1h TTL) backs
`get_max_leverage`/`get_coin_index`, warmed at server startup by
`services/risk/api.py::prewarm_coin_specs` for every desk coin
(`pathiel/server.py::_prewarm_size_specs`) — confirmed live at ~2.3s cold,
~0ms warm. The Account page's venue read (`fetch_account_state`, 11 dexes,
~1s cold) is also already behind a shared, cached snapshot
(`pathiel.client.account_snapshot`) — correctly NOT further cached, since
equity has to be live, not stale.

**Shell + per-section loading panels (point (a)).** All three pages already
rendered their shell at once (masthead, nav, section headings) with no
server-side blocking — the remaining gap was look and granularity, not
architecture:

- A shared `.spinner` rule (`pathiel.css`, one `@keyframes`, a
  `prefers-reduced-motion` opt-out) replaces every bare "Loading…" text with
  a spinner + the section's own title — same look on all three pages.
- `account.html` had **no loading or error state at all** — its two
  sections (`#account-section`, `#risk-section`) rendered dashes
  (`&mdash;`) with nothing to say a fetch was in flight, which on the ~1s
  cold venue read looked identical to broken. Both sections now get the
  same three-state pattern the Desk/Thesis pages already used
  (`#<prefix>-loading`/`#<prefix>-error`/`#<prefix>-body`, a small inlined
  `setSectionState()`), each failing independently — a dead account read no
  longer has any effect on the risk editor, and vice versa.
- `oil_desk.html`'s Wallets, Levels and Headlines sections had an error
  state but no loading state at all (they simply rendered blank until their
  fetch resolved); each now gets the same spinner panel, shown at the start
  of its own `loadWallets()`/`loadLevels()`/`loadCall()` and hidden on
  success or failure.

### 2. Thesis tab ignores the selected desk

`pathiel.js` gets a `PathielDesk` module: `get()`/`set()` persist the
selected desk id in `localStorage` (`pathiel.activeDesk`), and
`repointThesisLink()` rewrites every page's `#nav-thesis-link` href/data-nav
to `/desk/{that id}` (falling back to `oil`), re-running the (also newly
exported) `markActiveNav()` so the Thesis tab highlights correctly wherever
it points. Wired in:

- **Desk page** (`oil_desk.js`): `loadActiveDesks()` now prefers the stored
  desk over `activeDesks[0]` (so a reload keeps the desk you were on), and
  the switcher's radio `change` handler calls `PathielDesk.set()` before
  repointing.
- **Thesis page** (`desks.js`): new `loadActiveDesksForSwitcher()` renders
  the same tab row as the Desk page's `#desk-switcher` (added to
  `desk.html`) — one active desk means no row, several show the tabs;
  picking one navigates to `/desk/{id}` (there is no in-place re-render on
  this page, so the navigation itself is the "re-fetch"). `initDeskPage()`
  also calls `PathielDesk.set(deskId)` on arrival — viewing a desk's thesis
  directly (a bookmark, a link) makes it the stored selection too, not just
  picking a tab.
- **Account page**: no page-specific script of its own needed — `pathiel.js`
  loads first on every page and repoints `#nav-thesis-link` once the DOM is
  parsed (`DOMContentLoaded`; `pathiel.js` itself loads from `<head>`, before
  `<body>`, so the repoint can't run any earlier than that).
- The `g`-then-`t` keyboard shortcut (`pathiel.js`) now follows the same
  stored desk instead of a hard-coded `/desk/oil`.
