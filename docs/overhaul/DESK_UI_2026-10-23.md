# Desk UI (agent: desk-ui, 2026-10-23)

Branch: `oil-desk-ui` off `overhaul-2026-10-17` at `4b4f817`, rebased onto
`434312b` (`grade-everything` + `mcp-oil-only` + `headless-desk` merged).

Operator decision, 2026-10-23: pathiel is a headless desk. Claude runs a
15-minute MCP loop (`.claude/skills/oil-tick/SKILL.md`) that trades a small
pathiel wallet through `place_bracket`/`bracket_sweep`
(`pathiel/agents/bracket.py`); the operator trades their own wallet by hand
at their own chosen leverage from the same thesis. The dashboard that used
to watch the autonomous bot (scan feed, book panels, AI-brain trend tab,
trade tape) has nothing left to watch. This agent rebuilds it around the
new workflow: one screen, the decision first, small tables, nothing to
hunt for — vanilla HTML/CSS/JS served by the FastAPI server, no framework.

**The product is a generic desk UI, not an oil-only one.** Other
`DeskSpec`s (`btc`, `top5`, `ai`, `metals`, `indices`) stay registered in
`services/strategies/desks/*.py`, reachable by a direct link or a script.
The UI only shows desks listed in agent config's `active_desks` (default
`["oil"]`) — one active desk renders with no switcher, several show a
small tab row (the switching code stays wired either way). Oil is the only
desk actually trading today, not the identity: the plan is to master oil
first, then turn on indices, ETFs and other commodities the same way.

## The one screen: "/" (the Desk page)

Sections, top to bottom (`pathiel/templates/oil_desk.html`,
`pathiel/static/oil_desk.js`):

1. **Onboarding** (`#onboarding-root`) — shown instead of the Desk, for a
   brand-new visitor only: connect account → risk preset → done. Ported
   verbatim from the old landing page, minus the per-book feasibility
   preview (books are gone).
2. **The call** (`#call-section`) — the active desk's thesis in quick
   markdown (`services/thesis/render.py::render_markdown`, the same
   renderer the MCP `desk_brief` tool uses in quick mode), plus the 20x
   line: liquidation price, stop distance as a share of it, a plain
   verdict ("20x OK" / "no 20x: max Nx"), and R to each target — computed
   from the call's own entry/stop/targets by
   `services/strategies/call_line.py`, using `pathiel/agents/bracket.py`'s
   `check_levels`/`check_leverage` and `pathiel.client.exchange.
   get_max_leverage`. A 5/10/20 leverage selector recomputes it
   server-side (`GET /api/desks/{id}/line?leverage=`). The same line
   renders on the Thesis tab's leverage picker, via the same endpoint.
3. **Wallets** (`#wallets-section`) — one row per registered account (the
   active trade account and every watch account): equity, each position
   with entry/leverage/liquidation/distance/uPnL, its stop and target
   levels, and a red NAKED badge when no reduce-only stop covers it.
   `GET /api/accounts/{id}/positions`
   (`services/accounts/positions.py::fetch_positions_for_account`, moved
   out of `scripts/watch_wallet.py`'s `assess()`), across the main dex and
   every HIP-3 dex the account holds margin on.
4. **Levels** (`#levels-section`) — mid, last closed 1h candle, 8h/24h/48h
   range, ATR14, where the mid sits in the 24h range, for the active
   desk's primary instrument. `GET /api/desks/{id}/levels`
   (`services/strategies/levels.py::summarize_coin`, moved out of
   `scripts/oil_levels.py`).
5. **Headlines and catalysts** (`#intel-section`) — the intel the thesis
   already carries (`DeskBrief.intel`/`.thesis.catalysts`): upcoming
   catalysts, the top headlines by relevance with a bull/bear/neutral
   chip, prediction-market odds. A Hormuz/ceasefire headline is the loop's
   invalidation trigger, so it belongs on the one screen, not only buried
   in the full thesis. Capped to 6 rows per list (small tables).
6. **Loop log** (`#log-section`) — the last 30 lines of the active desk's
   loop. `GET /api/desks/{id}/log` (`services/strategies/desk_log.py`,
   moved out of... itself, generalized from oil-only to
   `PATHIEL_<DESK>_LOG` per desk id, `PATHIEL_OIL_LOG` unchanged for
   `desk_id="oil"`). Missing file renders "no ticks yet".
7. **Track record** (`#track-section`) — `DeskBrief.track_record` (n
   graded, direction hit rate, mean return, mean Brier).
8. **Old auto-trader kill switch** (`#stop-section`) — the STOP TRADING
   control survives, relabeled: it sets agent config `mode: OFF`, which
   only disables the retired bot's own `execute` path. It does not stop
   the oil-tick loop (`place_bracket`/`bracket_sweep`) or the operator's
   own trades — the label says so, because an off switch people misread
   is worse than no off switch.

Refreshes every 30s via `pathiel.js`'s `pollEvery` (never stacks a poll
behind a slow read, pauses while the tab is hidden). Every section loads
and fails independently — one source failing shows that section's own
inline error, never a blank page.

## What survives underneath

`pathiel/dashboard.py` keeps every function a route outside the deleted
pages still calls, verified by grepping the whole repository (not just
this file) before deleting anything — several near-misses turned up this
way: `_risk_payload`/`_closed_trades_payload`/`_equity_curve_payload`/
`_derived_limits_for` back `pathiel/metrics.py`'s `/metrics` endpoint and
their own dedicated test suites; `_positions_payload`/
`_positions_payload_uncached` have independent regression coverage for a
fallback-caching behavior unrelated to any page;
`_summary_payload`/`_feed_health` back `GET /api/health/system`;
`_viewer_account_payload` backs the surviving `GET /api/dashboard/account`;
`_rows_from_state` has its own dedicated test file
(`tests/test_open_reason.py`); `_trends_payload`/`_start_trend_job`/
`_refresh_lane_subprocess`/`_TREND_LANES` are untouched per the explicit
instruction to leave `services/trend_engine` alone. `GET /api/dashboard/
risk` and `/positions` stay mounted (operator-gated) for exactly these
reasons, even though no page renders them any more.
